# Шаблоны синхронизации скриптов: Файловый семафор (QUIK / QLUA)

При обмене данными между разными скриптами в QUIK или связкой QLUA + внешняя программа (Python, C#, др.) файловый обмен является самым стабильным и независимым от сторонних DLL способом.

Для предотвращения ситуации, когда читатель обращается к ещё недописанному файлу, используются 2 проверенных варианта семафора.

---

## 📌 Вариант 1: Классический файл-маркер (Флаг-разрешение)

### Логика работы:
1. **Писатель** создаёт и наполняет файл data.txt.
2. После закрытия файла (io.close) писатель создаёт рядом пустой файл-маркер data.ready (или lag.lock).
3. **Читатель** в цикле проверяет наличие data.ready.
4. Как только data.ready обнаружен — читатель забирает данные из data.txt и **удаляет** data.ready (сигнализируя, что данные прочитаны).

### Плюсы:
- Предельно наглядно, легко отлаживать глазами в проводнике Windows.

---

## 📌 Вариант 2: Атомарное переименование (Через временный файл .tmp)

### Логика работы:
1. **Писатель** создаёт и пишет данные во временный файл data.tmp. Читатель на него вообще не реагирует.
2. После закрытия файла (io.close) писатель делает мгновенное переименование: os.rename("data.tmp", "data.txt").
3. В файловой системе NTFS/Windows переименование происходит **атомарно** (мгновенно в один шаг).
4. **Читатель** просто проверяет data.txt — он физически не может наткнуться на «недописанный» файл. Прочитал -> удалил data.txt.

### Плюсы:
- Не нужен отдельный второй файл-флаг.
- Исключён любой риск рассинхрона между записью данных и появлением флага.

---

## Важные нюансы реализации для QUIK:
1. **Таймаут зависшего флага**: при использовании Варианта 1 читатель должен проверять время жизни флага, чтобы при падении писателя система не заблокировалась навечно.
2. **Кодировка**: текстовые данные при обмене между Lua и Windows-приложениями должны сохраняться с учётом кодировки (Windows-1251 для QUIK или UTF-8 по согласованию).
