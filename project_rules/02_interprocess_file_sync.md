# 02. Правила синхронизации скриптов и файлового обмена (Файловый семафор)

## 1. Общие принципы
1. Прямое одновременное чтение и запись в один и тот же файл без синхронизации **запрещены** во избежание состояния гонки (race condition) и чтения недописанных данных.
2. Для синхронизации работы скриптов в QLUA и взаимодействия с внешними процессами используются **2 стандартных паттерна файлового семафора**:

---

## 2. Варианты семафора

### 📌 Вариант 1: Классический файл-маркер (Флаг-разрешение)
* **Алгоритм**:
  1. Писатель создаёт и наполняет data.txt.
  2. После io.close писатель создаёт пустой файл-маркер data.ready (или lag.lock).
  3. Читатель проверяет появление data.ready.
  4. При обнаружении флага читатель считывает data.txt и удаляет data.ready.

### 📌 Вариант 2: Атомарное переименование (Через временный файл .tmp)
* **Алгоритм**:
  1. Писатель формирует данные во временном файле data.tmp.
  2. После io.close писатель переименовывает файл через os.rename("data.tmp", "data.txt").
  3. Читатель открывает data.txt только тогда, когда он появился целиком. Прочитал -> удалил.

---

## 3. Защита от сбоев
* При использовании Варианта 1 обязательна проверка таймаута существования флага, чтобы исключить вечную блокировку при аварийном завершении писателя.
